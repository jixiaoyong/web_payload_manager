Flutter App 内的 Web 内容热更新管理方案Hot-update management for web content in Flutter apps

让 Flutter App 的 Web 内容离线可用、更新可控，嵌入式 WebView 管理版本化资源：优先加载本地内容，在后台检查更新，并在安全时机切换到已验证的新版本。比小程序方案更轻量；相比在线加载 H5，加载更快，不惧弱网。Keep web content in Flutter apps available offline and updates under control. Manage versioned assets in an embedded WebView: load local content first, check for updates in the background, and switch to a verified new version at a safe time. Lighter than a mini-program approach; faster to load than online H5, and resilient to weak networks.

面向真实集成场景Built for real-world integrations

把资源下载、校验、存储和本地加载整合到 Flutter 应用中。Bring asset downloads, validation, storage, and local serving together in your Flutter app.

01

本地优先，后台更新Local-first, background updates

从内置或已验证资源启动页面；更新在后台准备，不打断当前模块会话。Launch from bundled or verified assets. Updates prepare in the background without interrupting the current module session.

02

安全下载与校验Secure downloads and validation

支持 ZIP 资源包、断点续传、文件完整性校验，以及安全路径和解压限制。Supports ZIP asset bundles, resumable downloads, file integrity checks, and safe path and extraction limits.

03

通过本地 HTTP 加载Serve over local HTTP

使用回环地址为 WebView 提供本地资源，并可按模块管理资源版本与入口。Serve local assets to WebViews over a loopback address, with per-module asset versions and entry points.

一次更新是怎样完成的How an update works

远端只提供版本清单和静态资源包；下载、验证、安装与切换由宿主 App 中的 Flutter 包管理。The remote host provides only a version manifest and static asset bundles; the Flutter package in the host app manages downloading, validation, installation, and activation.

01

检查远端版本清单Check the remote version manifest

应用启动或业务触发检查时，组件请求开发者配置的 version.json 或更新 API。清单描述最新版本、ZIP 地址、包校验值，以及可选的最低宿主版本和强制更新信息。When the app starts or the host triggers a check, the package requests the developer-configured version.json or update API. The manifest describes the latest version, ZIP URL, package checksum, and optional minimum host version and mandatory-update information.

若本地版本已是最新、网络不可用或处于纯内置模式，可以继续使用当前可用资源；更新不要求 Web 页面先从网络加载。If the local version is current, the network is unavailable, or the app is using bundled assets only, the available assets remain usable. Updates do not require the web page to load from the network first.

02

下载资源包到暂存区Download the asset bundle to staging

发现新版本后，组件将 ZIP 下载到应用沙盒的临时位置。下载过程支持进度回调与断点恢复，避免网络中断后必须从头开始。When a newer version is found, the package downloads the ZIP to a temporary location in the app sandbox. Progress callbacks and resume support avoid restarting from scratch after a network interruption.

清单和下载地址由业务服务或静态托管提供；GitHub Pages 在本项目中只是一个公开演示更新源的例子。The application service or static hosting provides the manifest and download URL. GitHub Pages is only an example of a public demo update source in this project.

03

验证内容并安全安装Verify content and install safely

安装前检查包完整性与清单中的文件校验信息，再校验 ZIP 条目路径和解压规模，拒绝路径穿越、不允许的文件类型或超出限制的内容。Before installation, the package checks bundle integrity and manifest file checksums, then validates ZIP entry paths and extraction size. It rejects path traversal, disallowed file types, and content exceeding configured limits.

只有验证成功的文件才会进入应用管理的版本目录；失败的下载或解压不会替换当前可用版本。Only verified files enter the app-managed version directory. A failed download or extraction never replaces the currently available version.

04

继续使用当前会话，择机切换Keep the current session; switch at a safe point

组件通过本机回环 HTTP 服务把已安装模块提供给 WebView。当前页面使用不可变的资源快照；新包准备好后，宿主可在页面重开等安全边界激活新版本。The package serves installed modules to the WebView over a local loopback HTTP server. The current page uses an immutable asset snapshot; once a new bundle is ready, the host can activate it at a safe boundary, such as when reopening the page.

这样可避免资源更新过程中同一个页面混用新旧文件，也让应用掌握何时切换，而不是强制打断用户。This prevents a page from mixing old and new files during an update and lets the app choose when to switch, rather than interrupting the user.
